# 第一次接入业务项目

业务项目不需要提前复制任何本项目文件。

## 操作

1. 把真实项目目录交给聊天端，或让聊天端能读取对应远端仓库。
2. 明确说“初始化这个项目”。
3. 聊天端先读项目必要入口，不扫描全部历史。
4. 聊天端建立该项目自己的 `.ai/`。
5. 聊天端重新读取刚写入的文件，确认路径和内容完整。
6. 从此以后，换聊天时从 `.ai/` 恢复。

## 第一次建立的目录

```text
.ai/
├─ INDEX.md
├─ context/
│  ├─ PROJECT.md
│  ├─ ARCHITECTURE.md
│  ├─ MEMORY.md
│  └─ DECISIONS.md
├─ tasks/
│  └─ ACTIVE.md
└─ handoff/
   └─ CURRENT.md
```

第一份正式任务出现时建立 `TASK-xxxx.md`。

第一份执行结果出现时再建立 `reports/` 和对应结果文件。

## 不放进业务项目的东西

- `聊天端/CHAT_CORE.md`
- `执行端/AGENTS.md`
- `执行端/角色/`
- 本项目的安装说明
- 本项目的维护和原项目跟进文件

这些都是 Chat-Git-Agent 自己的安装材料，不是业务项目内容。

## 如果没有 GitHub

直接使用本地目录即可。`.ai/` 与业务代码一起保存在本地项目中。

## 如果使用 GitHub

把 `.ai/` 当作项目正常文件一起同步。聊天端或执行端从远端读取时先同步到本地；执行结束后再按授权同步回远端。
