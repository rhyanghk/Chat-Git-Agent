# Control Data Source Protocol

协作控制项目需要一个唯一的正式控制资料库。平台 Project 可以是使用界面，但当它不具备可靠版本历史时，必须另指定正式资料库；不得通过备份、副本或镜像制造第二个事实源。

## 记录类别与权威

| 记录 | 正式位置 |
| --- | --- |
| 通用规则与 Skill 分发 | 本仓 |
| 控制项目指令与控制角色 | 当前协作控制项目及其正式资料库 |
| 项目代码、项目约束与项目证据 | 对应业务项目 |
| github_relay 任务与回写结果 | 指定业务 GitHub 项目的指定位置 |
| 本地执行现场 | 非正式；只作为当前任务工作区 |

## 正式对象

使用 PROJECT、TASK、R、DISPATCH、WORK、REPORT、DECISION、EVIDENCE 的固定编号。编号分配由 primary Project Architect 负责。每个对象只有一个正式位置。

## 控制资料最小集

- 当前项目注册记录；
- 当前有效的项目约束与 decision；
- 当前任务与 revision；
- 任务派发和结果报告的正式位置；
- 当前状态与下一步。

不要保存完整聊天记录、隐藏推理或无关探索。
