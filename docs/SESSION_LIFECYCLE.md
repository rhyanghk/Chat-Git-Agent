# 会话、恢复与交接

**分类：L2 场景参考。** 仅在启动恢复、控制角色交接、会话丢失或状态冲突时读取；普通任务不默认读取。

## 1. 哪些内容可以作为事实

- 唯一正式资料库、当前正式任务、项目版本记录与任务报告可以恢复和核验。
- Chat 会话、临时附件、旧提示和模型记忆只是工作记忆，不是任务合同。
- 本地执行工作区只服务当前任务；不覆盖他人现场，也不能替代正式记录。
- GitHub 只在任务声明 `transport: github_relay` 时成为该项目的远端事实位置；没有该声明时，不能假设 GitHub 可用或必需。

当来源冲突时，优先级为：当前有效的正式任务与实时项目状态 → 经授权的正式 decision → 任务点名的项目资料 → 缓存或摘要 → 聊天记忆。

## 2. 新会话或冷启动

执行 Agent 只读取：当前执行规则、精确任务、当前角色规则和任务点名的项目文件。然后执行七项开工检查：角色、入口、授权、访问、当前任务、边界与当前状态。

Chat 控制角色只读取：短项目指令、当前控制角色规则、启动卡中的唯一正式资料库，以及当前事项点名的记录。

缺少角色、项目、资料库、任务、访问、权限或一致状态时，返回 `BLOCKED`；不得扫描全部历史、所有项目、全部任务或整机文件来补全上下文。

## 3. 同一任务恢复

只有同一任务、同一 revision、同一角色且现场可解释时使用 `startup_mode: resume`。恢复时只刷新：

1. 当前正式任务及其状态；
2. 当前角色规则和任务点名的资料；
3. 当前项目现场、工作分支或本地工作区；
4. 上次报告后的新 decision、验证或阻塞记录。

任务 revision、项目状态或工作分支出现无法解释的变化时，停止并报告 `BLOCKED`。不要通过重读全部历史或原地改写任务恢复。

## 4. GitHub 中继恢复

仅对 `github_relay` 任务：在读取任务、实施、验证与回写前都刷新远端引用，同步任务声明的完整项目树，并比较任务基线、默认分支、main（如存在）、工作分支与本地状态。远端不可刷新时报告 `BLOCKED_REMOTE_SYNC`；变化无法解释时报告 `BLOCKED_REMOTE_DRIFT`。

同步不授权默认分支写入、force push、merge、deploy、release 或删除任何分支。详细字段见 `30_PROTOCOLS/GITHUB_RELAY_PROTOCOL.md`。

## 5. 控制角色交接

交接只转移 AI 工作流的协调职责，不转移 Human 的目标、组织权限、GitHub 权限或商业决定权。

1. Human 指定接任的 `Global Architect` 或 `Project Architect`。
2. 交出方在正式资料库留下当前项目、活跃事项、已冻结边界、风险与下一步的精确指针。
3. 接任方读取该指针和当前实时记录，验证不存在并行 primary 控制角色。
4. 使用 `architect_handoff_check.md` 完成接收检查；通过后使用 `architect_handoff_transaction.md` 写入接受记录。
5. 未通过前不派发新任务、不施工、不接受结果。

## 6. 最小派发 Seed

Seed 只定位正式任务，不携带第二份合同：

```text
task: TASK-000001-R001
role: Builder
startup_mode: fresh
```

只有上述三行不能无歧义找到正式任务时，才加入最少的 `authority_source` 或 `transport` 路由字段。scope、forbidden、acceptance、历史结论和验证步骤都保留在正式任务内。

## 7. 会话命名与结束

会话名称仅方便 Human 查找，不是事实状态。执行角色完成任务后，在任务指定的唯一正式位置提交报告，并停止等待验收；提交、验证、接受和发布是不同动作。控制角色在会话结束前将任何必要的当前指针写回正式资料库，而不是保存完整聊天记录。
