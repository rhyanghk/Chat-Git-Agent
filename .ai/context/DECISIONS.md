# 已接受的重要选择

## D-001

决定：采用“聊天端安装 / 执行端安装 / 业务项目零预装”。

理由：让通用规则不污染业务项目，同时让聊天端和执行端可以跨项目复用。

影响：业务项目第一次接入后只生成项目自己的 `.ai/`。

来源：人于 2026-08-22 明确要求。

## D-002

决定：GitHub 不是运行前提，只用于同步和版本记录。

理由：本地文件即可完成任务；远端不可用不应阻塞正常执行。

影响：任务启动提示必须支持本地路径和 `revision`；使用 GitHub 时才额外使用精确提交号。

来源：人于 2026-08-22 明确要求。

## D-003

决定：跟随原项目更新采用“精确提交 + 对应表 + 人工吸收变化”，不做目录镜像或自动覆盖。

理由：既能持续吸收原项目有效改进，又不会把复杂术语和 GitHub 依赖重新带回来。

影响：维护 `维护/跟随原项目更新.md`、`维护/对应表.md`、`维护/更新记录.md`。

来源：人于 2026-08-22 明确要求。
