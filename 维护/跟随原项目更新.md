# 跟随原项目更新

本项目保留易更新性，但不镜像原项目目录，也不自动复制原项目新文件。

## 当前核对基线

```text
source_repository: youling/ai-use
last_checked_ref: 1ddfeb0dd6a606dbc80ab86de8903d6888077bc6
checked_date: 2026-08-22
```

## 永远先保留的本项目边界

原项目以后怎么变化，都不能自动推翻下面这些已经由人明确确定的规则：

1. 聊天规则只安装在聊天端。
2. 执行规则只安装在执行端用户目录。
3. 业务项目第一次接入前零预装，由聊天端首次接入后建立项目自己的 `.ai/`。
4. GitHub 只用于同步和版本记录；没有 GitHub 时本地流程仍能完成。
5. 人能看到的说明优先使用通俗简体中文，不把原项目的复杂叫法照搬回来。

如果原项目新规则与以上边界冲突，先报告给人决定，不自动吸收。

## 每次更新只做六步

1. 找到原项目最新精确提交。
2. 从 `last_checked_ref` 比较到新提交。
3. 只检查 `维护/对应表.md` 列出的当前有效入口和这次新增的真正行为规则。
4. 判断变化会不会影响：人的最终决定权、任务格式、启动检查、角色边界、结果证据、独立检查、交接、安全或阅读范围。
5. 有影响时，用本项目现有的简单说法修改对应文件；不要复制原项目目录、编号、英文术语或历史说明。
6. 运行 `检查清单.md`，记录新 `last_checked_ref` 和本次吸收内容。

## 什么叫“跟随更新”

跟随的是行为和边界，不是文件数量和文件名。

原项目新增一百篇解释文档，如果没有改变实际工作规则，本项目可以不新增文件。

原项目只改一条重要权限边界，本项目必须更新对应规则。

## 不使用 GitHub 时怎么办

本项目自己的日常工作不受影响。

要跟进原项目新版本时，只需要能取得原项目的新文件包或新版本内容；取得后仍按同一张对应表比较。本项目不会因为远端不可用而阻塞普通项目任务。
